## 0. Финальные решения заказчика
- **Решение 1:** Сервер: Supabase на базе Postgres. Разработка ведется на Supabase.
- **Решение 2:** Гостевой режим не нужен. Игра только после регистрации.
- **Решение 3:** Регистрация: по почте или через Google.
- **Решение 4:** Порог голосования «Давайте заканчивать»: большинство для варианта «Закончить после круга», единогласие для варианта «Закончить сразу».
- **Решение 5:** Кнопка «Закончить сразу» добавляется.
- **Решение 6:** Опция «Что скажет ИИ про наш рассказ» включается уже в версию 1.0.
- **Решение 7:** Видимость: игрок видит всю фразу предыдущего игрока целиком.
- **Решение 8:** Выполняется обязательная версия 1.0.

## 1. Объем версии 1.0
- **Классика:** видна только полная фраза предыдущего игрока.
- **Порядок:** фиксированная очередь или жребий перед каждым ходом.
- **Завершение:** по кругам, по числу фраз, по времени, по голосованию.
- **Участники:** вход до старта, выход, пропуск, неактивность, пауза.
- **Финал:** полный текст, авторство, реакции, кнопка ИИ.
- **Сервер:** Supabase, один бэкенд для регистрации, игры и хранения рассказов.

---

## 2. Сервер Supabase
### 2.1. Состав проекта
- **Supabase Auth:** регистрация и вход по почте и через Google.
- **Supabase Database:** Postgres таблицы `users`, `rooms`, `room_members`, `phrases`, `votes`, `final_stories`, `ai_analyses`.
- **Supabase Realtime:** подписки на изменения комнаты.
- **Supabase Edge Functions:** серверные функции для логики ходов, видимости и вызова ИИ.

### 2.2. Схема базы данных
- `users`: id, name, avatar_url, auth_provider, created_at.
- `rooms`: id, room_code, name, topic, starting_phrase, settings, state, host_id, created_at, started_at, finished_at.
- `room_members`: id, room_id, user_id, role, status, queue_order, passes_count.
- `phrases`: id, room_id, author_id, phrase_number, text, round, is_passed, created_at.
- `votes`: id, room_id, vote_type, initiator_id, votes_data, result, created_at.
- `final_stories`: id, room_id, full_text, authors_data, created_at.
- `ai_analyses`: id, story_id, analysis_result, created_at.

### 2.3. Безопасность видимости
- Прямой запрос к `phrases` запрещен политиками Row Level Security (RLS).
- Клиент получает предыдущую фразу только через серверную функцию `get_current_turn_phrase()`.
- Финал открывается только через функцию `get_final_story()`.
